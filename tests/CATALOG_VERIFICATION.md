# UI 1.4.0 공개 캐릭터·지역 데이터 연결 (2026-10-09)

## 연결한 원본

- `characters/npc_roster_100.json`: 100명/마수 유형의 레벨, 5능력치, HP/MP, 속도, 기초 공격.
- `characters/core_cast_stats_38.json`: 군주·영주·성자/성녀·기사단장·탑주 38명.
- `characters/serin.json`: 기존 세린의 공개 정체성 연결 항목. 기존 원본에 숫자가 없어 사용자 결정 전까지 미정으로 유지한다.
- `locations/regional_dungeons_facilities.json`: 영주령별 26개 던전·26개 시설을 지도 목록과 GPT 탐색/방문 요청에 연결.

빌드에서 공개 필드만 `web/catalog-data.js`에 생성한다. GM 전용 설정, NPC 메모·성격 seed, 미발견 던전 방은 포함하지 않는다. 기존 캐릭터 원본의 능력치·이미지·좌표를 수정하지 않았다. 정치적 지위를 기사 경지로 표시하지 않는다. 마수 배율은 REBALANCE_V2의 별도 잠정 값을 읽는다.

## 엔진 연결

정보창과 상태창의 인물 능력치 목록, 브리지 `getNPC(id)` 및 `getNPCCatalog()`, GPT 요청의 현재 NPC, 전투 시작 검증은 같은 데이터 모델을 사용한다. NPC 변화는 `updateNPC(id,changes)` 또는 장면 `npc_updates`에 의해 선택적인 `npcStates`에 저장한다. 전투 종료 HP/MP도 여기에 반영한다. 초기 GitHub 값 재조회로 부상·마나·관계를 초기화하지 않는다.

등록된 원화가 없는 인물은 `outfit=none`으로 데이터·대사를 연결한다. 세린 이미지를 재사용해 다른 인물처럼 보여주지 않는다. 기존 세린 표정 합성과 브리지·세이브 v1을 유지한다.

캐릭터 및 지역 JSON 변경 시 GitHub Actions가 번들을 다시 생성하도록 감지 경로를 확장했다. 런처의 기존 안전한 UI 업데이트 적용을 사용한다. 동작 중인 전투에 새 초기 수치를 섞지 않는다. 원격 자동 빌드 실행은 GitHub Actions의 성공 여부에 따라 반영된다.

## 추가 설정 검토

작업 중 main에 추가된 던전 구역, 기술서 70권, 전리품 규칙, 장소 이미지 제작 목록, 깃발 시안을 확인해 보존했다. GPT의 관련 행동/전투 요청에 DUNGEON_STRUCTURE/BOOKS_SYSTEM/LOOT_SYSTEM 참조를 추가했다. 승인 대기 깃발과 제작 전 배경을 런타임 승인 이미지로 등록하지 않았다. 장비 장착 UI, 기술서 학습 전용 화면, 던전 구역 이동·최초 클리어 전리품의 별도 자동 엔진은 이번 변경에 포함하지 않는다. 실제 현지 이동·입장·보상·학습은 기존 GPT 턴 판정과 구조화 응답으로 진행한다.

## 검증

`node --test tests/*.test.mjs`: 기존 41개 + 데이터/브리지/장면/마수 검증 7개, **48개 통과**.

원본 138명 전원의 수치 일치, 공개 필드 제한, 오래된 저장에 새 키를 넣지 않는 것, NPC 변경 저장 왕복, 현재 NPC GPT 컨텍스트 및 브리지 일치, 원화 없는 등록 인물의 장면, 잘못된 NPC 전투 수치 거절, 등록 마수 배율, 새 UI 요소의 HTML 연결을 확인했다. 로컬 게임 주소의 HTTP 응답은 200이다.

사용자가 직접 실험하는 방침에 따라 이번 변경의 실제 브라우저 클릭·ChatGPT 송수신·모바일 터치는 수행하지 않았다. 코드 검사 통과를 실제 플레이 성공으로 기록하지 않는다.
