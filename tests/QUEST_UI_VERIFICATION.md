# UI 1.6.0 의뢰·전투·전송 확인

## 확인된 코드 검사

- 84개 Node 테스트 통과. 제안/수락, 실제 던전 증거, 전투 토벌, 인벤토리 획득, 발행자 보고, XP/아이템/재화/호감도 정산, 중복 방지, 실패/포기/만료, 저장 호환 검사 포함.
- 실제 생성한 게임 번들과 런처 구문 검사 통과. bridge/state/scene 버전은 1.
- 클릭·숫자키·Enter가 action 메시지를 생성함, 입력창에서는 숫자키 무시, 전송 실패/잘못된 JSON 후 버튼 잠금 해제 확인.
- 1.1.6 런처의 새 게임 전송이 자동 첨부 미지원으로 차단되지 않음. 첨부가 있다고 주장하지 않고 GitHub 직접 읽기 요청으로 전환함.
- 전투 수동 진행 기본값, 각 사건 종료 후 무기한 읽기 대기, 주인공 스탠딩 숨김, 마나 바 갱신, 자동 재생 및 정확히 한 번 정산 확인.

## 실제 브라우저에서 확인한 범위

tests/quest-demo.html은 원래 게임 번들을 sandbox=allow-scripts iframe에서 실행한다. 실제 세이브와 분리된 테스트 저장/GM 응답을 사용한다.

확인: 타이틀 표시/불러오기 → NPC 개인 제안 카드 → 수락 요청과 등록 → 던전 진입 증거에 따른 보고 가능 전환 → 발행자 복귀 → 완료 보고 → XP14/재화5/등록 철검/호감도2 한 번 지급 → 중복 보고 거절 → 저장 복원. 현지 게시판 조회 응답, Q/숫자키, 390px iframe 모바일 너비에서 의뢰 필터·카드 표시 확인.

실제 사용자 Chrome의 ChatGPT/Tampermonkey, GPT가 생성한 의뢰, 파일 첨부와 실제 전송의 성공은 이 로컬 데모 검증과 구분한다. 사용자 화면은 런처 1.1.6으로 확인됨. 전체 설정 파일 첨부를 사용하려면 1.1.7로 업데이트 필요. 데모 성공만으로 실제 ChatGPT 연결 성공을 주장하지 않는다.

추가 실제 UI 확인: 전투 첫 사건이 읽기 대기에서 유지되고 다음 턴 클릭 시에만 두 번째 사건으로 진행됨. 즉시 종료 후 토벌 의뢰가 ready_to_report로 변경되고 전투 XP45만 한 번 적용됨. 실패/포기/기한 만료는 각각 새 분리 저장으로 실행해 해당 필터의 카드 표시까지 확인. 최신 기본 게임의 타이틀·두 메뉴를 캡처함(artifacts/ui-title-fixed.png).
