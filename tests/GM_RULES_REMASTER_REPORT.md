# GM 규칙 리마스터 검증 — 2026-10-11

## 변경과 원인

일반·축약 요청(`actionPrompt`)과 연속 요청(`incrementalPrompt`)이 별도의 긴 운영 지침을 만들었다. 빠른 실행, 새 위험에서 멈춤, NPC 지식, 후일담, 정산 조건이 서로 다른 순서와 표현으로 반복되었다. 이 구조는 실제 코드에서 확인했다. 이것만이 모든 서술 문제나 GM 지연의 원인이라고 입증한 것은 아니다.

`GM_OPERATING_RULES.md`를 공통 기준으로 만들고 서술·편의·의뢰 문서를 역할별로 정리했다. 두 요청 경로는 `web/gm-turn-policy.js`의 같은 운영 규칙·응답 계약을 사용한다. 현재 행동·현장 인물·진행 위협·검증된 결과를 요청 앞에 배치하고 뒤의 실제 엔진 기록은 유지한다. 장면 요약의 중복 사본은 요청 표시에서 제거하며 동기화 기준·저장·원장·검증을 바꾸지 않는다. 전문 지침은 관련 행동에서만 제공한다. 기존 공개 export 이름은 공통 규칙의 별칭으로 유지한다.

세계관·능력치·성장·가격·계약 조건·전투 판정은 변경하지 않았다. 장면/저장/브리지 버전 1 유지, UI 2.1.97.

## 실제 GM과 엔진에서 확인한 결과

로그인된 내장 브라우저의 기존 ChatGPT GM(Instant)과 컴파일 엔진을 수동으로 연결했다. 사용자 저장과 분리한 `qa-rules-remaster-20261011` 저장을 사용했다. 합성 GM 응답은 사용하지 않았다. 실제 관찰 구간은 한국 시간 00:14:38~00:31:02(약16분24초, 응답 대기 및 중간 수정·검증 병행 포함)이다. 행동8회/완료 GM 응답9회/적용8회이며 생성 중 응답의 조작 실수로 재요청1회가 추가되었다. 같은 실제 위협 저장을 복원해 두 대응을 비교했다. 같은 GM 채팅에 앞 분기의 대화가 남아 있으므로 독립된 무작위 대조 실험은 아니다. 최신 checkpoint가 실제 진행의 기준임을 확인했다.

공통 의뢰: 브란 오크펠의 **방책 보수용 목재 운송**, 보수 60동/XP12. 수락·적재·출발이 한 응답에서 진행됐다. 09:55에 수레가 기울며 아래 작업자 두 명과 브란이 위험해졌다. 이 발견 턴에서 자동 해결하지 않고 대응 선택지를 남겼다.

| 대응 | 실제 결과 | 완료 시각 | 정산 |
| --- | --- | --- | --- |
| A: 작업자 대피와 브란 철수 우선 | 인명 피해 없음. 통나무 3개 이탈, 빈 받침대 일부 파손, 경사로 통행 막힘. 일꾼 도움으로 수습·운송·인계·보고 | 10:45 | 560동, XP12, completed |
| B: 바퀴와 결속 고정 우선 | 바퀴가 멈췄지만 작업자 위험은 남음. 이 단계에는 보수·목표 완료를 지급하지 않음(500동, 목표0, active). 이어 대피·추가 고정 후 낙하·파손 없이 인계·보고 | 10:43 | 560동, XP12, completed |

두 분기는 모두 HP100/MP100을 유지했다. 보수는 선택 보너스를 발명하지 않고 같은 계약으로 한 번 정산했다. `story_events`의 실제 위협/해결 기록과 목표 증거·보고가 저장에 연결됐다. A의 받침대 파손이 B 저장에 복사되지 않았다. 플레이어의 수습·인계·보고 실행을 다시 준비 질문으로 되돌리지 않았다.

짧은 실제 예시:

- A: 브란 — “사람은 모두 무사하군. 잘 판단했어.” 이후 **“목재는 모두 인계되었지만 사고로 부서진 빈 받침대는 수리가 필요했다.”**
- B: 브란 — **“목재는 전부 도착했네. 부러진 것도 없고.”** 저장의 해결 근거도 목재 낙하·인명 피해 없이 처리한 것으로 기록됐다.
- 초기 제안/수락 응답에는 GM이 플레이어의 직접 대사를 임의로 붙였다(민하: “안녕하세요. 자재 운반 일을 구하고 있는데…”). 공통 규칙에 명시하지 않은 플레이어 대사·감정·핵심 대응을 만들지 말고 간접 묘사하도록 보완했다. 이후 A/B 실제 응답은 요청한 행동을 나레이션으로 진행했다. 동일 입력의 대조 검증이나 모든 향후 응답의 예방을 입증한 것은 아니다.

## 구현과 재플레이 검증 구분

- 공통 규칙/계약 통합, 전문 지침 선별, 앞쪽 장면 요약, 중복 요약 제거: 구현 및 자동 검사 통과.
- 수락·출발, 대응 후 수습·인계·보고의 한 턴 진전: 실제 GM/엔진 확인.
- 새 위협에서 플레이어 대응을 남김, 서로 다른 대응의 파손·후속 상황 차이, 미해결 상태의 지급 차단, 계약 보수 한 번 정산: 실제 두 분기 확인.
- 플레이어 대사 대리 생성 보완: 이후 실제 응답에서 관측, 동일 입력 예방은 미검증.
- 최종 빌드에서 B 완료 저장 복원·후일담·중복 정산 방지: 실제 확인. 브란은 바퀴 고정 뒤 대피시킨 순서를 기억했고 560동/XP12/completed/의뢰1건을 유지했다. 새 수락·재보상·위협 재시작 없음.

검사 514개 통과, 통합 빌드 완료, 매니페스트 SHA256 일치, 등록 이미지·오디오 1498개 누락0. Tampermonkey 자동 전달과 사용자의 업데이트 적용은 별도 미검증이다.

## 남은 문제와 속도

브란의 후일담이 두 분기 모두 인명 보호 칭찬·다음 경사로 점검으로 비슷하게 끝났다. 과묵한 등록 말투에 비해 긴 조언이 나와 공통 규칙의 말투·중복 요약 기준을 보완했다. B 완료 저장과 같은 질문을 복원해 실제 재플레이하자 대사/지문 합계558→273자로 줄었다(약51% 감소). 이전 장문의 “다음에는 세 가지를 기억하게…” 설명이 “다음엔 출발 전에 바퀴와 밧줄부터 확인하게…”로 짧아졌고 바퀴 고정·대피의 실제 기여와 560동/XP12/completed는 유지됐다. 같은 GM 채팅의 한 사례다. 남은 문제는 비슷한 위협의 반복 가능성과 전반적인 NPC 개성·감정의 깊이이며, 한 의뢰의 분기와 한 후일담의 개선을 전체 해결로 확대하지 않는다.

같은 위협 저장·같은 행동의 요청 길이를 이전 커밋 ce0d258과 비교했다. 전체 단일 요청 47,392→37,081자(약22% 감소), 연속 checkpoint 17,853→18,145자(약2% 증가), delta 10,003→10,955자(약10% 증가). 서술 맥락을 앞에 옮기는 구조 개선이며 전체 경로가 모두 빨라졌다는 결과는 아니다. 실제 수동 GM 왕복도 수십 초 걸렸고 생성 시간만 분리한 속도 개선은 입증하지 않았다. 큰 복원 저장/설정 규모와 모델 응답 지연은 남았다.

운영 중 아직 생성 중인 응답을 너무 일찍 적용한 조작 실수 1회가 있었다. 엔진이 불완전 JSON을 거절하고 새 요청 ID로 재요청했고, 완료된 실제 GM 재응답을 적용했다. 이를 GM이 완성 응답을 잘못 만들었다는 결함으로 집계하지 않는다. 원본 응답과 분기 저장은 비공개 QA 자료로 보존한다.
