# 응답 검증 오류 복구 — UI 2.1.1

기존 브리지·장면·세이브 버전 1 및 Tampermonkey 런처를 유지한다. 모바일 레이아웃은 변경하지 않는다.

## 작동

1. 사용자의 원래 행동과 요청 ID를 보관한다.
2. 런처에서 전달한 응답의 형식·전투·의뢰·세계 사건 검증이 실패하면 상태 변경 전에 거절한다.
3. 현재 저장 상태, 실제 검증 오류, 원래 행동을 포함하는 수정 요청을 최대 2회 보낸다. 화면에는 ‘응답 수정 중’을 표시한다.
4. 수정 요청은 새 requestId를 사용하되 원래 rootRequestId와 행동을 유지한다. 이전 요청의 늦은 응답과 다른 요청의 응답은 검증 전에 차단한다. 자동 전달 응답에는 현재 reply_to가 반드시 필요하다.
5. 정상 응답만 기존 정산 경로에 한 번 반영한다. 전투는 기존처럼 관전 종료 시 정산한다.
6. 2회 수정 후에도 실패하면 입력을 다시 활성화하고 ‘다시 요청’을 표시한다. 이 버튼은 원래 행동의 수정 요청을 한 번 보내며 자동 수정 횟수를 초기화하지 않는다. 새로운 자유 행동을 명시적으로 보내면 새 요청 묶음이 시작된다.

원래 행동을 바꾸거나 추가 턴을 진행하지 않도록 수정 프롬프트에 명시한다. 변경되지 않은 상태는 생략하도록 안내하지만 기존 전투의 필수 증빙과 종료 스냅샷은 유지한다. 엔진이 정산하는 보상을 별도 상태 스냅샷으로 중복 작성하지 않도록 안내한다. 기존 전투 스키마를 줄이는 전면 변경은 하지 않았다.

## 재전송하지 않는 경우

- 전송 오류, 런처 ACK 누락, 응답 시간 초과: 실제 전송 여부가 불확실하므로 자동으로 다시 보내지 않는다.
- 사용자가 JSON 수동 적용을 시도한 경우: 검증 오류를 표시하고 사용자의 다음 조작을 기다린다.
- 이미 상태 적용을 시작한 뒤의 화면·저장 오류: 새 턴으로 자동 재요청하지 않는다.
- 대기 해제 또는 저장 복원: 이전 요청을 종료하고 늦은 응답을 차단한다.

수정 중 전송 실패 시에도 ‘다시 요청’을 사용할 수 있다. 원본 ChatGPT에 이미 전송되었는지는 확인해야 한다.

## 범위

자동 복구는 **기존 런처가 게임 프레임에 전달한 응답**에 적용된다. 런처가 JSON을 찾지 못한 경우, 미완성 JSON 또는 응답 자체가 생성되지 않은 경우는 이 UI 패치로 자동 감지하지 못하며 기존 시간 초과/수동 복구를 사용한다. 프레임에 전달된 문법 오류는 수정 가능하지만, 모든 문법 오류가 기존 런처를 통과한다고 주장하지 않는다. 런처 재설치는 요구하지 않는다.

## 검증

추가 `tests/response-recovery.test.mjs` 8개: 2회 자동 수정·성공 1회 적용, 반복 실패 후 명시적 재요청, 잘못된/늦은 요청 ID 차단, 전달된 JSON 문법 오류, 전송 실패 시 자동 재전송 없음, reply_to 누락·수동 적용, 취소/저장 복원, 세계 사건 실패의 상태 원자성.

전체 자동 검사 148개 및 통합 빌드 통과. 실제 ChatGPT 서버·설치된 확장·장기 플레이 검증은 수행하지 않았다. 사용자가 직접 플레이 확인하는 범위를 존중해 브라우저 시연은 하지 않았다.
